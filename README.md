# 上海大学校园跑 · LOCATION LAB

> 一个纯前端的「校园跑轨迹实验室」：把田径场跑道还原成几何模型，在上面跑一遍路线、导出 `route.local.json`、再把真机回传的坐标丢回来验算它到底有没有落在跑道上。

**在线访问**：https://kevin0521-wjw.github.io/shu-location-lab/
**备用（本地打开）**：直接双击 `index.html` 即可，无需服务器。
**仓库**：https://github.com/kevin0521-wjw/shu-location-lab

---

## 它是什么

一个 59 KB 的单文件网页（HTML + CSS + Canvas，零依赖、零网络请求），做四件事：

| 模块 | 作用 |
|---|---|
| **路线沙盘**（`#map`） | 用真实几何参数画出嘉定校区田径场（直道 84.39 m、弯道半径 37.11 m、8 道），把 97 点环形路线叠上去，可播放/调速/复位，实时显示里程与用时 |
| **导出** | 一键下载与 SHUAutoRun 完全同格式的 `route.local.json`（首末点重复闭环），或复制坐标数组 |
| **位置反算**（`#check`） | 粘贴真机回传坐标（`lat lon` / `lon lat` 都认，也能直接贴整段日志），逐点算到路线折线的**最短距离**，判定是否落在跑道上 |
| **坐标系转换**（`#geo`） | GCJ02 ⇄ WGS84 双向换算，附上海地区约 500 m 偏移的实测对照 |

### 为什么判据是「到折线的最短距离」

标准 400 m 田径场是**跑道形**（两个半圆 + 两条直道），场内任意一点到中心的距离从 37 m 到 79 m 都可能是合法位置。所以「离跑道中心 60 m」这种判据毫无意义，只有**到路线折线本身的最短距离**才能说明问题。LOCATION LAB 用的是后者——本项目的真机实测中，回传坐标偏离路线中线 **≤ 0.41 m**。

## 路线数据从哪来

1. 取高德卫星瓦片 z=18（约 0.51 m/px）作为底图，人工标出内突沿与外突沿；
2. 用射线检测提取白色分道线像素，做 ICP 椭圆拟合，**锁死 b/a = 0.523**（标准跑道比例），避免被旁边的篮球场白线拉成 2.15:1；
3. 按 84.39 m 直道 + 37.11 m 半径重建几何，沿第 1 道中线等距采样 97 个点，单圈 **403.1 m**。

参数：中心 `31.377538, 121.249512`，长轴方位 153.5°，起点 `31.377346, 121.250060`，坐标系 **GCJ02**（高德 / 微信小程序用的火星坐标）。

> 宝山校区旧路线保留在 `data/route.baoshan.json` 作为对照（11 点 / 381.4 m）。

## 本地部署

三种方式，任选：

**1. 直接打开（最简单）**
双击 `index.html`。页面不加载任何外部资源，`file://` 协议下功能完整。

**2. 起一个本地静态服务器**
```bash
cd shu-location-lab
python serve.py            # 默认 http://127.0.0.1:8080
python serve.py 9000       # 换端口
```
或者不用脚本：
```bash
python -m http.server 8080
```

**3. 丢进任意静态托管**
Nginx / Apache / GitHub Pages / Vercel / Netlify 都能直接用——这是一堆静态文件，没有构建步骤：

```
index.html          # 站点本体（数据已内联）
data/*.json         # 路线原始数据，供下载与二次加工
.nojekyll           # GitHub Pages 用，关掉 Jekyll 处理
serve.py            # 本地起服务
```
